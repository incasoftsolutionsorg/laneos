## 1. How screens are built

- **Stack.** Next.js 16 App Router (server components by default; `'use client'` only for interaction), Tailwind v4 with the tokens in `packages/ui/src/theme.css` (Appendix E.6). Never raw hex in components except one-off design colours listed in §5.
- **Data.** Server components read through `requireTenant()` (`lib/server/context.ts`), which gives the signed-in member, permissions, tenant and current shop. Reads use RLS-protected tables or `api.*` read functions; every write goes through an `api.*` function or a server action that calls one. Money and quantities use `@laneos/core` helpers.
- **Figma.** Frames were read with the Figma MCP (design context for new layouts, screenshots for screens assembled from existing components). Icons are Lucide, recoloured with `currentColor` (the Figma SVGs are Lucide shapes).
- **Permissions.** Pages call `requireTenant('<permission>')`; buttons for actions the member cannot do are not rendered.
- **Not built yet** screens render `<Planned>`: the design's title, the milestone, and a link to the Figma frame. No fake data and no buttons that do nothing.

## 3. Lane (checkout) behaviour

| Topic | Behaviour |
| --- | --- |
| Device registration | `/lane/register` (or the PIN screen) registers the browser for a lane. The device key is kept in IndexedDB and sent as `X-Lane-Key`; registering again moves the lane to the new device. |
| Cashier sign-in | A registered lane opens on **Who is selling?** (PIN pad). The cashier's PIN unlocks the lane; sales, shifts and returns are recorded against them. 5 wrong PINs lock that cashier for 15 minutes. Unregistered lanes sell as the signed-in staff member (set-up / training). |
| Idle lock | A registered lane locks after the tenant's "Lane locks after" minutes (default 3) without a key press or tap; an unfinished bill is held first. **Lock** in the lane bar locks at once. |
| Keyboard | F1 search · F2 quantity · F4 void last line · F6 price check · F7 customer · F8 hold · F9 recall · F12 pay. Scanner input goes to the search box (Enter = scan). |
| Prices | The lane prices the basket with `@laneos/pricing`; the server re-prices and refuses a different total (`PRICE_MISMATCH`), after which the lane reloads its catalogue. |
| Payments | Cash (quick-cash chips, change due), card / LankaQR (reference only), credit note (online only; code checked by hash), **on account** (online only; a credit customer attached with F7, within their limit — the server re-checks), or split. Change only from cash. |
| Held bills | Kept on the lane (localStorage), cleared at shift close. |
| Offline | If the server cannot be reached the sale is saved on the device (IndexedDB) and synced with backoff (5 → 60 s). The lane bar turns red; credit notes, member look-up and returns are not available offline. A sale the server refuses at sync goes to **Back office → Sync issues**. Invoice numbers: if the shift reserved numbers, the receipt shows the final number; otherwise it says "Number at sync". |
| Receipts | Printed through the browser (`/lane/print`) until QZ Tray is wired. Online receipts carry a QR code to the digital receipt `/r/<token>`. |
| Customer display | **Display** in the lane bar opens `/lane/[id]/display` in a second window; it follows the basket on the same device (BroadcastChannel). |
| Shifts | Open: count the float by note, optionally reserve 200 invoice numbers. Close: count the drawer, see expected cash and variance (note required if not zero), print the Z-report. Cash pickups lower expected cash. A lane with unsynced offline sales cannot close. |
| Returns | Lane → **Return**: find the bill, choose lines/qty/reason, sellable or damaged, then cash (supervisor PIN above the tenant limit, default Rs 5,000), original method, exchange, credit note or credit balance. Bills paid by credit note refund only to a credit note. |

## 5. Differences from the Figma file

| Screen | Design | Built | Why |
| --- | --- | --- | --- |
| Refunds (1-2808) | "Approval needed" card with pending refunds approved later in the back office | Supervisor approves with a PIN at the lane at the moment of the refund | No refund is ever left half-done; `returns.approved_by` records the approver |
| Payment (1-1159) | "Send receipt by SMS" | Not shown | No SMS gateway yet |
| Customer display (11-2973) | LankaQR "Scan to pay" QR | Not shown | Needs the merchant's LankaQR data |
| Return (1-2580) | "Exchange now: add new items to this return" | Issues an exchange credit note to spend straight away at the checkout | One sale flow for all new items; the credit note keeps the value safe |
| Lane bar (1-549) | Shop · lane · status · shift · cashier · clock | Adds Display, Return, Close shift, Lock and Back office links | The lane needs a way to reach these screens |
